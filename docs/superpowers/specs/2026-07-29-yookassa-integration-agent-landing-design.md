# Дизайн лендинга YooKassa Integration Agent

Дата: 29 июля 2026 года  
Статус: визуальное направление утверждено пользователем

## Результат

Нужно создать адаптивный одностраничный лендинг устанавливаемого Codex-плагина `yookassa-integration-agent`.

Лендинг должен помочь разработчику:

- понять, зачем нужен агент технической интеграции;
- увидеть основные функции и границы безопасности;
- понять порядок работы с агентом;
- установить плагин из GitHub;
- перейти к официальной документации и исходному коду.

### Визуальная система

- Светлый фон, белые поверхности и темно-синий текст.
- Основной акцент — насыщенный синий.
- Зеленый используется только для подтвержденных успешных проверок.
- Шрифт: Inter или близкий свободно доступный гротеск.
- Тонкие границы, небольшие радиусы, почти отсутствующие тени.
- Крупный, спокойный hero с большим количеством свободного пространства.
- Одна центральная колонка шириной до 1200 пикселей.
- Линейная подача деталей вместо сетки из рекламных карточек.
- Стандартные интерфейсные иконки из Phosphor Icons; никаких самодельных SVG, CSS-рисунков и emoji.

## Структура страницы

### 1. Шапка

- Собственный знак из готовой иконки.
- Название `ЮKassa Integration Agent`.
- Подпись `Локальный плагин для Codex`.
- Якоря `Возможности`, `Как установить`, `Документация`.
- Ссылка на GitHub.

### 2. Hero

- Заголовок: `От первого запроса до проверенной интеграции`.
- Краткое описание: агент работает рядом с разработчиком в Codex и превращает требования в план, код, проверки и диагностические доказательства.
- Основная кнопка: `Установить из GitHub`.
- Вторичная кнопка: `Как это работает`.
- Факты: дата проверки источников, локальная работа, тестовый контур.

### 3. Четыре этапа

1. Спроектировать.
2. Реализовать.
3. Проверить.
4. Диагностировать.

При выборе этапа рабочая область меняет активный контент. Этап `Реализовать` выбран по умолчанию.

### 4. Демонстрация рабочей области

Три части:

- диалог разработчика с агентом;
- фрагмент TypeScript-кода;
- результаты проверок и состояние `Готово к тестированию`.

Демонстрация не выполняет API-запросы и не имитирует финансовые операции.

### 5. Пять специализированных skills

- `integration-planner`;
- `implementation`;
- `receipts-54fz`;
- `diagnostics`;
- `integration-review`.

Каждая строка содержит название и одно точное описание результата.

### 6. Установка и первый запрос

Точные команды:

```bash
codex plugin marketplace add Belolipetsky/YooKassa-MCP --ref main
codex plugin add yookassa-integration-agent@yookassa
```

После установки пользователь должен открыть новую задачу Codex.

Кнопки копирования должны работать и показывать краткое подтверждение.

### 7. Официальные источники

- API ЮKassa;
- OpenAPI ЮKassa;
- Webhooks ЮKassa;
- тестирование интеграции;
- чеки и 54-ФЗ;
- 54-ФЗ на сайте ФНС;
- Stripe Agents;
- Stripe Skills;
- Stripe MCP;
- GitHub-репозиторий проекта.

### 8. Безопасность и ответственность

Показать без маркетингового преувеличения:

- плагин не выполняет финансовые операции;
- живая диагностика разрешена только для тестового магазина;
- MCP предоставляет только read-only инструменты;
- проверка чеков не заменяет консультацию юриста, бухгалтера или специалиста по ККТ.

## Поведение

- Якорная навигация прокручивает страницу к нужному разделу.
- Основные CTA ведут к секции установки и на GitHub.
- Четыре этапа переключают содержимое демонстрационной области.
- Кнопки копирования используют Clipboard API и имеют состояние успеха.
- Все интерактивные элементы доступны с клавиатуры и имеют видимый focus.
- Внешние ссылки открываются в новой вкладке с безопасными `rel`-атрибутами.

## Адаптивность

- Desktop: визуально соответствует референсу при ширине 1440 пикселей.
- Tablet: hero и рабочая область переходят в одну колонку.
- Mobile: навигационные ссылки скрываются, этапы превращаются в горизонтально прокручиваемый ряд, рабочая область и секция установки становятся одноколоночными.
- Горизонтальный overflow страницы запрещен.

## Техническая форма

- Отдельный Product Design prototype в каталоге `landing/`.
- React, TypeScript, Vite и CSS.
- Контент хранится в типизированных структурах данных.
- Основной UI разделен на небольшие компоненты по секциям.
- Backend, формы, аналитика, auth и реальные вызовы ЮKassa не входят в задачу.

## Проверка

- TypeScript и сборка проходят без ошибок.
- Основные интеракции проверены в браузере.
- Desktop и mobile экраны визуально проверены.
- `design-qa.md` содержит сравнение с референсом и `final result: passed`.
