# Чек-лист проектирования

- Определены покупатель, товар/услуга, момент оплаты и бизнес-результат.
- Выбран одно- или двухстадийный платеж.
- Описаны capture, cancel, полный и частичный refund.
- Есть таблица допустимых переходов заказа и объектов ЮKassa.
- `Idempotence-Key` создается один раз на бизнес-операцию и сохраняется.
- Redirect не используется как доказательство оплаты.
- Webhook повторно получает объект через API и работает идемпотентно.
- Секреты находятся только на сервере.
- Сценарий чеков согласован с ответственным за ККТ/налоги.
- Есть тесты повторов, timeout, ошибок API и webhook race.
- Перед релизом проверены OpenAPI и changelog ЮKassa.
